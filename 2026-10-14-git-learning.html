约定式提交

类型(范围): 简单描述

其中范围可选, 不兼容的时候在冒号前使用 ! 标记, 类型如下

类型 用途 示例
feat 新功能 feat: 添加暗色模式
fix 修复 bug fix: 修复文章目录跳转错误
docs 文档修改 docs: 补充本地运行说明
style 代码格式调整，不影响含义 style: 统一缩进和引号
refactor 重构，既不新增功能也不修复 bug refactor: 提取文章加载逻辑
perf 性能优化 perf: 缓存文章索引
test 添加或修改测试 test: 添加搜索功能测试
build 构建系统、依赖调整 build: 升级 vite
ci CI 工作流调整 ci: 添加自动部署流程
chore 其他维护工作 chore: 更新 gitignore

PR 的创建与合并

自己的 Repo

  1. 从最新的 main 创建开发分支
    git switch main
git pull --ff-only origin main
git switch -c dev
  2. 修改提交推送
    # change sth...
git add . && git commit -m "chore: ..."
git push -u origin dev
  3. PR
    # 在网页端发起 PR, base 选择希望合并入的分支 (通常是 main), compare 选择 dev
# 因为是自己的分支, 可以自己检查合并 PR
  4. 合并之后更新本地 main
    git switch main
git fetch origin main
git merge --ff-only origin/main     # ff only 是快速前进合并, 当且仅当本地是远程的祖先, 如果不是需要 merge 或 rebase  
                                    # merge 的话是手动处理冲突, 然后合并
  5. 如果本次工作完成, 可以删掉
    git branch -d dev
git push origin --delete dev        # 远程删除 dev 分支
git fetch --prune origin            # 清理本地残留的 origin/dev 远程跟踪引用

别人的 Repo

  1. fork 他人的 repo, 下面以 self/prj 指代 fork 的项目, oth/prj 指代原项目
    git clone https://github.com/self/prj.git
cd prj
git remote add upstream https://github.com/oth/prj.git
git remote -v                       # 查看相关信息
  2. 从原项目最新的 main 创建开发分支
    git switch main
git fetch upstream
git merge --ff-only upstream/main

git push origin main                # 同步自己的远程 fork
git switch -c dev                   # 从最新的 main 创建开发分支
  3. 修改提交推送到自己的 fork
    # change sth...
git add . && git commit -m "chore: "
git push -u origin dev
  4. 发起 PR
    base repo: 原作者仓库;  
base: main;  
head repo: 自己的 fork 仓库;  
compare: dev;
  5. PR 合并之后更新本地仓库
    git switch main
git fetch upstream                  # 同步已经更新到原仓库
git merge --ff-only upstream/main   # 合并原仓库的 main
git push origin main                # 将最新的 main 推送到自己 fork 上
  6. 删除开发分支
    git branch -d dev
git push origin --delete dev
git fetch --prune origin

一些其它概念

git pull 实际上如下

git fetch origin            # 下载 origin 的新提交
git merge origin/main       # 将远程的 main 分支合并到本地的 main 分支

所以 Git 工作流的主体结构大概是这样的

  • 本地通过 git remote add NAME REMOTE_REPO_URL 来连接远程仓库, 每个 NAME 有两个地址, fetch 地址和 push 地址, 通常相同;
    fetch 和 push 操作指名 NAME 的时候, 就分别使用同名的地址; 可以通过 git remote -v 来查看远程仓库信息
  • fetch 只是下载, pull 整合了下载和合并, fetch 和 push 的常见用法如下
    git fetch NAME            # 获取远程的所有分支更新
git fetch NAME BRH        # 获取远程的具体某条分支更新
git branch -r             # 查看获取的远程分支信息
git push NAME BRH         # 将本地 BRH 分支推送到远程同名分支
git push NAME BRH:RMB     # 将本地 BRH 分支推送到远程 RMB 分支
git push -u NAME BRH      # 推送到远程分支并设置本地的跟踪关系
git push --dry-run NAME BRH   # 预览推送操作

track 是设置上游跟踪关系, 即本地的 xx 分支和远程的 yy 分支关联, 首次推送也会设置关系
例如

git switch -c dev --track origin/dev    # 在本地创建 dev 分支并跟踪远程的 dev 分支
git push -u origin dev                  # 将本地的 dev 分支上传到远程的 dev 分支, 并使本地的 dev 分支跟踪远程的 dev 分支
git branch --set-upstream-to=origin/dev dev # 两个分支已经存在, 仅设置关系
